# 진짜 병목은 GitHub 분이 아니라 API 일일 한도였다 (2026-09-01)

## 무슨 일이

run 10 이 20초 만에 죽었습니다. `점검(doctor)` 단계에서 실거래가 API 가
**429 Too Many Requests** 를 돌려줬습니다.

```
FAIL 실거래가 API 호출 실패
  → HTTPError: 429 ... apis.data.go.kr/1613000/RTMSDataSvcLandTrade/...
```

## 어디서 막았는가 — Vercel 이 아니라 국토부

같은 doctor 실행에서, 같은 중계기를 통과한 다른 호출은 몇 초 차이로
정상이었습니다.

```
2. API 키        ok   중계기 .../api/relay
3. 실거래가      FAIL 429
4. VWorld 지오코딩 ok   좌표 회신 (37.40210, 127.10864)
5. 도로공사 API   ok   영업소 10건 회신
```

Vercel 이 함수를 막았다면 4번·5번도 같이 죽었을 것입니다. 살아 있으므로
**우리 키가 국토부 쪽에서 막힌 것**입니다.

## 왜

어제 run 9 가 5시간 50분 동안 만 건이 넘는 호출을 했습니다. 공공데이터
포털 **개발계정은 일일 트래픽이 작습니다**(API 마다 다르고 1,000~10,000건
수준). **운영계정은 최대 10만 건**입니다.

우리 작업 한 번이 최소 11,280 요청(94 시군구 × 60개월 × 2종)이고
페이지네이션까지 더하면 그 이상입니다. **개발계정으로는 하루에 한 번을
못 끝냅니다.**

## 내가 반쪽만 봤다

Actions 분이 모자란다고 보고 동시 요청을 넣었습니다. 그 자체는 맞는
개선입니다 — 벽시계 시간과 Actions 분이 줄어듭니다. 그런데 **막고 있던
것은 속도가 아니라 총량**이었습니다. 동시 요청은 총량을 줄이지 않습니다.
오히려 한도에 더 빨리 닿습니다.

"5시간이 걸린다" 는 증상에서 속도 문제만 읽고, 그 5시간 동안 **몇 번을
불렀는지**는 세어보지 않았습니다. 셌으면 한도가 먼저 보였을 것입니다.

## 해야 할 것

1. **운영계정 전환** (대표님) — 공공데이터포털 → 마이페이지 → 오픈API →
   개발계정 → 해당 API → **운영계정 전환 신청**. 활용 사례를 적어 내면
   보통 승인됩니다. 이게 진짜 해법입니다.
2. 그때까지는 하루 한도만큼씩 나눠 받습니다. 재개가 정확히 동작합니다 —
   실패한 셀은 `status='error'` 로 남고 `done_cells()` 가 그것을 제외하므로
   다음 실행이 다시 시도합니다. 조용히 빠지지 않습니다.
3. 한도는 날짜가 바뀌면 초기화됩니다.

## 남겨둘 것

동시 요청과 차단 감지는 그대로 둡니다. 운영계정이 되면 그때는 속도가
다시 병목이 되고, 그때 이 개선이 값을 합니다. 연속 실패 40건에 멈추는
장치도 이번 같은 경우에 남은 셀을 헛되이 태우지 않게 해줍니다.
