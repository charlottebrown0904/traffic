49개가 전부 경기·인천권입니다. 전남·경북·강원의 IC 는 주변 거래에 좌표가
없어 한 줄도 못 올라왔습니다.

**전국 자료를 받는 것과 전국을 분석하는 것은 다른 일입니다.** 지금은
앞의 것만 됐습니다.

## 이번 실행에서 잃은 것 — 두 개의 조용한 사고

### 1. 2시간 33분을 마치고 마지막 한 줄에서 죽었다

전 단계가 성공하고 '결과 커밋' 에서만 실패했습니다. 두 가지가 겹쳤습니다.

- **얕은 클론.** `actions/checkout` 기본이 depth 1 이라 원격 브랜치와의
  공통 조상을 모릅니다. 그 상태로 rebase 하면 git 이 모든 파일을 '양쪽이
  각자 새로 만든 파일' 로 봅니다. 40개 파일이 전부 add/add 충돌했습니다.
- **대상 브랜치 고정.** 브랜치에서 돌렸는데 push 는 `HEAD:main` 이었습니다.
  충돌이 없었어도 그 브랜치의 코드 변경이 통째로 main 에 올라갔습니다.
  `analyze.yml` 에는 이미 고쳐 뒀는데 `collect.yml` 로 옮기지 않았습니다.

고쳤고(`fetch-depth: 0` · `github.ref_name`), 커밋이 막혀도 결과를
받아볼 수 있게 아티팩트 업로드를 넣었습니다. `scripts/test_workflows.py`
가 모든 워크플로에서 이 두 가지를 검사합니다.

전남 22시군구, 27개 시군구가 전국에서 조용히 빠졌습니다. 197개는 제
코드가 스스로 찍은 경고("230개 안팎이 정상")에 걸리는 숫자였습니다.

원인은 한 줄이었습니다.

```python
except Exception:
    return code, 0        # '호출이 막혔다' 가 '이 코드는 없다' 가 된다
```

`tollgate_fill.py` 에서 `CallFailed` 로 이미 한 번 고친 실수인데, 이쪽으로
옮기지 않았습니다. 이제 실패는 `None`(모른다) 로 돌아오고, 실패한 코드만
한 번 더 물어보며, 시도가 통째로 비면 그 자체를 사고로 보고 경고합니다.
