# 부동산통계정보(R-ONE) Open API — 무엇을 쓸 수 있나 (2026-09-12)

요청: "부동산통계정보 사이트 api 신청 완료. 이용 가능한 것이 있는
지 확인 바랍니다." 올려 주신 파일 다섯 개를 다 읽었습니다. 결론부터:

> **네, 있습니다. 시점수정의 원천이 여기 있습니다.**
> 그리고 예상 밖의 것 두 개가 더 나왔습니다 — **순수토지 거래량**과
> **역세권 지가지수**입니다. 요청제한횟수는 **없습니다**(명세서 기재).

올려 주신 파일이 무엇이었는지:

| 파일 | 실제 내용 |
|---|---|
| `OpenAPI_____.xls` | 확장자는 xls, 실제로는 **HTML 표** — 통계표 목록 **635개** |
| `______________API___.xls` | 명세서 — 서비스 통계목록 (`SttsApiTbl`) |
| `_____________API___.xls` | 명세서 — 통계 세부항목 (`SttsApiTblItm`) |
| `___________API___.xls` | 명세서 — 통계 조회 (`SttsApiTblData`) |
| `1789231346981___________.xls` | 진짜 옛 엑셀(BIFF8) — **토지가격비준표** 주거지역 한 장 |

마지막 것은 R-ONE API 와 무관한 별개의 수확이라 따로 적었습니다 →
`docs/bijunpyo.md`.

## 1. API 의 모양 — 세 개가 한 줄로 이어진다

```
SttsApiTbl      https://www.reb.or.kr/r-one/openapi/SttsApiTbl.do
SttsApiTblItm   https://www.reb.or.kr/r-one/openapi/SttsApiTblItm.do
SttsApiTblData  https://www.reb.or.kr/r-one/openapi/SttsApiTblData.do
```

세 개 모두 기본인자가 같습니다.

| 변수 | 값 |
|---|---|
| `Key` | 인증키 (**대문자 K**) |
| `Type` | `xml` 또는 `json` |
| `pIndex` | 페이지 위치 (1부터) |
| `pSize` | 페이지당 건수 — **최대 1,000** (넘기면 오류 336) |

요청인자와 주요 출력값:

| 엔드포인트 | 필수 | 선택 | 주요 출력 |
|---|---|---|---|
| `SttsApiTbl` | — | `STATBL_ID` | `STATBL_ID` `STATBL_NM` **`DTACYCLE_CD`** `DATA_START_YY` `DATA_END_YY` `OPEN_STATE` `RPSTUI_NM`(기준시점) |
| `SttsApiTblItm` | `STATBL_ID` | `ITM_TAG` | `ITM_ID` `PAR_ITM_ID` `ITM_NM` `ITM_FULLNM` `UI_NM` |
| `SttsApiTblData` | `STATBL_ID` `DTACYCLE_CD` | `WRTTIME_IDTFR_ID` `GRP_ID` `CLS_ID` `ITM_ID` `START_WRTTIME` `END_WRTTIME` | `GRP_NM`(대개 시도) `CLS_NM`(대개 시군구) `ITM_NM` **`DTA_VAL`** `UI_NM` `WRTTIME_DESC` |

메시지 코드 중 **꼭 구분해야 하는 둘**:

- `290` 인증키가 유효하지 않음 → 중계기의 `REB_KEY` 문제.
- `200` **해당하는 데이터가 없음 — 오류가 아닙니다.** 조건에 맞는 칸이
  빈 것뿐입니다. 이것을 예외로 던지면 빈 칸이 많은 시군구에서 수집이
  통째로 멈춥니다 (`src/redt/collect/reb.py` 는 구분해 다룹니다).

### 함정 하나 — 주기코드를 추측하지 않는다

`SttsApiTblData` 는 `DTACYCLE_CD` 를 **필수**로 받는데 명세서에 코드값 표가
없습니다. 틀린 값을 넣으면 오류가 아니라 **`200` 자료 없음**이 옵니다.
그러면 "이 표에는 자료가 없구나" 로 읽습니다 — RTMS 시군구 코드에서 이미
같은 함정에 빠진 적이 있습니다(잘못된 코드에 0건이 옵니다).

그래서 `cycle_of()` 가 **`SttsApiTbl` 목록에서 읽어 옵니다.** 코드에
`"MM"` 같은 값을 적어 넣지 않았습니다.

## 3. 길 — 코드와 워크플로

```
src/redt/collect/reb.py       세 엔드포인트 + TABLES(우리가 고른 20개 표)
scripts/reb_stats.py          --probe / --items ID / --pull 이름
.github/workflows/reb-stats.yml   Actions → '지가변동률 수집'
```

이 상자(미국 러너)에서는 `www.reb.or.kr` 로 직접 나갈 수 없습니다. 서울
중계기(`api/relay.js`)를 거칩니다 — ALLOW 에 이미 있었고, 이번에
**인증키 주입**을 붙였습니다.

```js
"www.reb.or.kr": { param: "Key", env: "REB_KEY", optional: true },
```

`optional: true` 인 이유: 같은 호스트가 **키 없는 공개 화면 읽기**에도
쓰입니다(`scripts/reb_probe.py`). 키가 아직 없으면 500 으로 막지 않고
통과시켜, 키를 받기 전에도 화면 탐침이 계속 됩니다.

## 4. 필요한 것 (사용자) — 두 단계, 클릭 먼저

### 4-1. 먼저 재십시오 (키 없이, 클릭 한 번)

```
Actions → 지가변동률 수집 → mode: reach → Run workflow
```

키를 어디에 넣을지가 이 출력으로 정해집니다(왜 그런지는 §5). **키가
없어도 됩니다** — 키 없이 부르면 R-ONE 이 `코드 290`(인증키 무효)으로
답하는데, 그 응답이 왔다는 것 자체가 '러너에서 닿는다' 는 증거입니다.

### 4-2. 그다음 키를 넣습니다

| reach 결과 | 넣을 곳 |
|---|---|
| 직접이 **된다** | GitHub → Settings → Secrets and variables → Actions → `REB_KEY` |
| 직접이 **안 된다** | Vercel → 이 프로젝트 → Settings → Environment Variables → `REB_KEY` (Production, 저장 후 **재배포**) |

**둘 중 하나면 됩니다. 양쪽에 넣지 마십시오** — 러너에 있으면 러너가
직접 부르고, 없으면 중계기로 갑니다. 양쪽에 있으면 러너 쪽이 이기므로
Vercel 값은 쓰이지 않고, 키 사본만 하나 더 생깁니다.

**키를 여기(대화)에 붙이지 마십시오.** 저는 몰라도 됩니다 — 지금까지의
모든 키가 그렇게 되어 있습니다.

### 4-3. 그리고 확인 → 받기

`mode: probe` 로 20개 표가 다 있는지·주기코드가 무엇인지·자료가 몇
년부터인지 찍고, 그 출력을 보고 `mode: pull` 로 **한 표씩** 받습니다.
`max_pages` 기본 40장이 안전장치입니다(§5-2).

## 5. 키를 Vercel 에 둘까 GitHub 에 둘까 — 한도 계산

질문: "키를 vercel 에 넣는 것이 맞는지, github 에 넣는 것이 한도에 관해
유리한지." 한도가 걸리는 자리가 **세 군데**인데 서로 다릅니다.

### 5-1. R-ONE 쪽 한도 — 키 위치와 **무관합니다**

명세서는 "요청제한횟수 제한없음" 이라 적으면서 오류 코드에는
`337 일별 트래픽 제한`을 둡니다. 둘 중 무엇이 실제인지는 많이 불러 봐야
알지만, 어느 쪽이든 **키 하나에 붙는 한도**입니다. 키가 Vercel 에 있든
GitHub 에 있든 R-ONE 이 보는 것은 같은 키이므로 **이 항목은 바뀌지
않습니다.**

한 가지만 다릅니다 — R-ONE 이 보는 **IP** 가 달라집니다.

  · 중계기 경유 → 서울 함수의 IP. 브이월드·KOSIS·법제처·포털 호출이
    **같은 IP 를 공유**합니다. 브이월드는 이미 분당 120회/IP 제한을
    받고 있습니다(`docs/deploy-vercel.md`).
  · 직접 → 러너 IP. 다른 수집과 섞이지 않습니다.

### 5-2. Vercel 쪽 한도 — **여기가 실제로 걸립니다**

중계기는 Vercel 함수입니다. 중계 호출 한 번이 곧 **함수 호출 1회 +
받은 바이트만큼의 Fast Origin Transfer** 입니다.

9월 11일 실측(`docs/deploy-vercel.md`):

| 항목 | 사용 | 한도 | 남은 것 |
|---|---|---|---|
| Function Invocations | 522K | 1M | 478K |
| Edge Requests | 785K | 1M | 215K |
| **Fast Origin Transfer** | **7.06GB** | **10GB** | **2.94GB** |

지가변동률 한 표의 전 기간을 받으면 얼마인가 — **추정**입니다(정확한
값은 `--probe` 가 `list_total_count` 로 알려줍니다):

```
시군구 약 250 × 용도지역 약 7 ≈ 월 1,750행
2010-01 ~ 2026-08 = 200개월 → 약 35만행
한 장 1,000행 → 약 350장 = 함수 호출 350회
한 행 약 350바이트(FULLNM 세 칸이 길다) → 약 120MB
```

  · 함수 호출 350회 = 남은 478K 의 **0.07%**. 무시할 수 있습니다.
    함수 호출은 사실상 `api/tile` 하나가 다 씁니다.
  · 전송량 120MB = 남은 2.94GB 의 **4%**. 한 표는 괜찮습니다.
  · **20개 표를 전부 전 기간 받으면 1~3GB** 입니다. 그건 남은 여유를
    거의 먹습니다. ← 이것이 진짜 위험한 쪽입니다.

매달 갱신분은 1,750행 = 2장 = 0.6MB 입니다. 아무것도 아닙니다.
**문제는 최초 backfill 한 번뿐입니다.**

### 5-3. GitHub 쪽 한도

러너가 직접 부르면 Vercel 함수 호출 **0회**, Fast Origin Transfer
**0바이트** 입니다. Actions 분은 오히려 **줄어듭니다** — 중계기 한 홉이
빠지니까요. 저장소가 private 이라 분은 과금 대상이지만, 350장이면 몇 분
안입니다.

### 5-4. 그래서 — 답

**재 봤습니다(§7). 직접이 됩니다 — 키는 GitHub Secrets 가 유리합니다.**
아래는 재기 전에 적은 논리이고, 결과는 §7 에 있습니다.

이유는 하나입니다. 러너가 직접 부르는 길이 **있는지 아직 재 보지
않았습니다.** 한국 공공 API 는 해외 IP 를 막습니다 —
`docs/finding-geoblock.md` 에서 `data.go.kr` 은 TCP 연결 자체가 완성되지
않았고, 브이월드·도로공사는 502·400 이었습니다. `www.reb.or.kr` 은
**측정 대상에 없었습니다.** 막혀 있으면 GitHub Secrets 는 아예 동작하지
않으므로, 재 보지 않은 채로 옮기는 것은 도박입니다.

**재는 것은 클릭 한 번이고, 키가 없어도 됩니다.**

```
Actions → 지가변동률 수집 → mode: reach
```

키 없이 부르면 R-ONE 은 `HTTP 200 + 코드 290`(인증키 무효)으로 답합니다.
**그 응답이 왔다는 것 자체가 '닿았다' 는 증거**입니다. 직접·중계기 두
길을 나란히 재서 판정까지 찍습니다.

| reach 결과 | 키를 둘 곳 | 이유 |
|---|---|---|
| 직접이 **된다** | **GitHub Secrets `REB_KEY`** | Vercel 함수 호출 0 · 전송량 0 · 공유 IP 도 안 씀 |
| 직접이 **안 된다** | **Vercel `REB_KEY`** (지금 방식) | 중계기 말고 길이 없음 |

**코드는 이미 양쪽을 다 받습니다.** `REB_KEY` 가 프로세스에 있으면 진짜
키가 들어가고 `http._should_relay` 가 '키가 있으니 돌아갈 필요 없다' 로
판단해 직접 부릅니다. 없으면 자리표가 들어가고 중계기가 바꿔 끼웁니다.
**환경변수를 어디 두느냐가 곧 어느 길로 가느냐이고, 갈림길이 코드에
없습니다** (`src/redt/collect/reb.py` `_query`).

`reb-stats.yml` 은 `secrets.REB_KEY` 를 읽지만 **없어도 그냥 돕니다**
(빈 값 → 중계기). 그래서 순서가 이렇게 됩니다.

1. `mode: reach` 한 번 — 키 없이. 어느 길인지 정해집니다.
2. 정해진 곳에 키를 넣습니다 (Vercel 또는 GitHub Secrets).
3. `mode: probe` — 20개 표와 주기코드 확인.
4. `mode: pull` — **한 표씩**. `--max-pages` 기본 40장이 안전장치입니다.

### 5-5. 보안은 어느 쪽이 나은가

'키는 중계기에만 둔다' 는 원칙은 지금까지 지켜 왔습니다. 다만 GitHub
Secrets 가 새로운 위험 등급은 아닙니다 — `REDT_RELAY_TOKEN` 과
`VERCEL_TOKEN` 이 이미 거기 있고, 그 둘이 R-ONE 키보다 위험합니다
(중계기 토큰은 우리 중계기를 열고, Vercel 토큰은 배포를 바꿉니다).

차이는 노출 면적입니다. 중계기에 두면 **Vercel 함수 하나**만 알고,
GitHub 에 두면 그 저장소의 **모든 워크플로와 그 워크플로가 쓰는 서드파티
액션**이 볼 수 있습니다. R-ONE 키는 공개 통계를 읽는 무료 키라 새어도
피해가 작습니다(과금 없음, 개인정보 없음). **한도 이득이 확인되면 옮길
값입니다.**

## 6. 아직 말할 수 없는 것

정직하게 적습니다. 목록(`SttsApiTbl.do`)은 불러 봤고(§7), 항목·자료
(`SttsApiTblItm.do`/`SttsApiTblData.do`)는 아직입니다.

1. **응답을 감싸는 모양** — 명세서는 출력 *항목*만 적고 봉투를 적지
   않았습니다. 기본인자(`Key`/`Type`/`pIndex`/`pSize`)가 서울 열린데이터
   광장과 같은 계열이라 `{"SttsApiTblData":[…,{"row":[…]}]}` 일 것이
   거의 확실하지만, 확실하지 않습니다. 그래서 파서를 그 모양에 못박지
   않고 **응답을 훑어 `row`/`RESULT` 를 찾습니다** (`reb._walk`).
2. **주기코드의 실제 값** — 목록에서 읽습니다(위 §1 함정).
3. **시군구까지 쪼개지는가** — `GRP_NM`/`CLS_NM` 이 시도/시군구일 것으로
   보이지만 표마다 다를 수 있습니다. `--probe` 뒤 `--items` 로 봅니다.
4. **일별 트래픽 제한** — 명세서에 "요청제한횟수 제한없음" 이라 적혀
   있으면서 오류 코드에는 `337 일별 트래픽 제한`이 있습니다. 둘 중 무엇이
   맞는지는 실제로 많이 불러 봐야 압니다. 그래서 수집기는 한 표씩,
   기간을 끊어 받습니다.

## 7. 첫 실측 (2026-09-12, GitHub Actions 러너 · mode: reach)

| 경로 | 직접 (미국 러너) | 중계기 (서울 icn1) |
|---|---|---|
| `/r-one/openapi/SttsApiTbl` (명세서 표기) | HTTP 200 · **HTML 'Page Not Found'** 7,057B | 같음 |
| `/r-one/openapi/SttsApiTbl.do` | HTTP 200 · **JSON `code=000 정상 처리되었습니다.`** 2,228B | 같음 |

세 가지가 정해졌습니다.

1. **경로에 `.do` 가 붙습니다.** 명세서 URL 그대로는 서버가 '없는
   페이지' 로 답합니다 — 키가 틀렸을 때의 `290` 이 아니라 HTML 입니다.
   그래서 처음에 키 문제로 오해할 뻔했습니다(`http.visible()` 로 오류
   문장을 앞으로 가져온 뒤에야 보였습니다). `reb.py` 의 `TBL`/`ITM`/`DATA`
   가 `.do` 로 바뀌었고, `reach` 는 두 후보를 나란히 두드려 JSON 이 오는
   쪽을 찍습니다.
2. **미국 러너에서 직접 닿습니다.** 지오블록이 없습니다(1초 안에 응답).
   §5 의 계산대로 대량 backfill 은 러너가 직접 부르는 쪽이 낫습니다 —
   Vercel 함수 호출 0회, Fast Origin Transfer 0바이트.
3. **목록 호출은 키 없이도 `000` 입니다.** 러너 쪽 `REB_KEY` 가 비어
   있었는데도 정상 응답이 왔습니다. 자료 호출(`SttsApiTblData.do`)도
   그런지는 모릅니다 — `mode: probe`/`pull` 로 확인합니다.

**키를 둘 곳 — 판정.** 지금은 Vercel 에 있습니다(중계기가 끼워 넣음).
동작에는 문제가 없지만 한 표의 전 기간(추정 120MB)이 Vercel 전송 한도를
갉아먹습니다(§5-2). 옮기려면 **GitHub → Settings → Secrets and variables →
Actions → `REB_KEY`** 에 넣고 **Vercel 쪽은 지웁니다** — 한 곳에만 둔다는
원칙(§4-2)입니다. 옮기지 않아도 `probe`·소량 `pull` 은 그대로 됩니다.
