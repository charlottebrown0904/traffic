# 가설3 자료 — 무엇을, 어디서, 어떤 모양으로

가설 3: **주변 시군구 인구·산업단지·대기업·택지지구가 들어오면 지가는 오른다.**

이건 세 번째 질문이면서 동시에 **1·2번의 답을 믿을 수 있게 만드는 조건**입니다.
IC 가 뚫린 그 해에 옆에 산업단지가 지정됐다면, 산단이 만든 상승을 IC 공으로
돌리게 됩니다. 이 자료가 없으면 H1·H2 는 계수가 유의하게 나와도 "IC 효과"라고
부를 수 없습니다.

## API 가 막힌 이유 (2026-09-02 확인)

`scripts/probe_h3.py` 를 돌린 결과입니다.

```
[15041930] 전국산업단지현황통계 (산단공)
    HTTP 200 · uddi 없음
...
어느 원천도 자료를 주지 않았습니다.
```

odcloud 는 데이터셋을 `uddi:xxxxxxxx-...` 로 부르는데, 그 uddi 가 포털
페이지에만 적혀 있고 **그 페이지는 자바스크립트로 그려집니다.** 서버가 주는
HTML 에는 없습니다. 서비스 이름을 추측하는 길은 NSDI 에서 이미 막혔습니다
(docs/land-price-fallback.md).

교통량도 똑같은 벽에 막혔고, 파일로 우회해서 지금 잘 돌아가고 있습니다
(`data/raw/tcs_annual_*.csv`). 같은 방법을 씁니다.

## 받아서 올릴 파일

`data/raw/` 에 넣고 이름만 아래 규칙에 맞추면 됩니다. **컬럼 이름은 안
맞춰도 됩니다** — 로더가 후보를 여러 개 놓고 찾아서, 무엇을 무엇으로 읽었는지
로그에 찍습니다.

### 1. 산업단지 — `zones_industrial.csv`

- 어디서: data.go.kr → "전국산업단지현황통계" 또는 한국산업단지공단
  팩토리온(www.kicox.or.kr) 통계자료실. **CSV/XLSX 내려받기 버튼**을 씁니다.
- 꼭 있어야 하는 칸: **지정일** (없으면 전후를 못 가릅니다)
- 있으면 좋은 칸: 단지명 · 단지구분 · 지정면적 · 위도·경도 · 소재지

### 2. 택지지구·도시개발 — `zones_housing.csv`

- 어디서: data.go.kr → "도시개발구역 현황" / LH 공공주택지구 현황
- 같은 규칙. 지정(고시)일이 핵심입니다.

### API 로 받는 것 (파일 업로드 불필요)

두 가지는 API 경로를 찾았습니다. 버튼으로 돕니다.

| 자료 | 워크플로 | 상태 |
|---|---|---|
| 도시개발사업(택지·도시개발) | **도시개발사업 받기** | 지정일이 오는지 실행이 말해줍니다 |
| 시군구 인구·사업체 | **KOSIS 목록 훑기** → 표 ID 확인 → 받기 | `KOSIS_KEY` 등록 필요 (docs/api-keys.md) |

KOSIS 는 두 걸음입니다. 자료를 받으려면 orgId(기관)·tblId(표) 를 알아야
하는데 그 값은 목록을 훑어야 나옵니다. 추측해서 적으면 **틀린 표의 숫자를
받아놓고도 맞는 줄 압니다** — RTMS 시군구 코드에서 이미 겪은 일입니다.
그래서 먼저 목록을 훑어 사람이 표를 고른 뒤에 받습니다.

### 3. 시군구 인구 — `region_population.csv`

- 어디서: 행정안전부 주민등록 인구통계(jumin.mois.go.kr) → 연도별
  시군구 인구. **여러 해가 한 파일에 있어야** 합니다.
- 꼭 있어야 하는 칸: **시군구코드(5자리)** · **연도** · 총인구
- 연도가 한 해뿐이면 변화율을 못 만들어 통제로 못 씁니다. 로더가 그 경우
  경고를 찍습니다.

### 4. 사업체·종사자 (선택) — `region_business.csv`

- 어디서: KOSIS 전국사업체조사 → 시군구별 사업체수·종사자수
- '대기업이 들어왔다' 를 직접 재는 공개 자료는 없습니다. 종사자수 증가가
  가장 가까운 대리지표입니다. 대리지표라는 사실을 결과에도 적습니다.

## 올린 뒤

```
python -m redt.cli load-h3      # 읽어서 적재 + 거래와 공간 조인
python -m redt.cli hypotheses   # 세 가설 판정
```

또는 GitHub 웹에서 `분석만` 워크플로를 `load_h3` 를 켜고 돌리면 됩니다.

## 로더가 스스로 지키는 것

- **면적 단위**를 헤더에서 읽어 ㎡ 로 환산합니다(천㎡·ha·㎢). 단위를 잘못
  읽으면 면적이 1000배 틀리는데, 회귀에서는 계수 크기만 달라져 눈에 안 띕니다.
- **지정일을 못 읽은 행은 버립니다.** 전후를 가를 수 없는 행은 이벤트가
  아닙니다.
- **한반도 밖 좌표는 비웁니다.** 잘못 찍힌 좌표 하나가 반경 밴드를 뒤집습니다.
- 좌표가 없는 건은 공간 조인에서 빠지고, 몇 %가 빠졌는지 찍습니다. 시군구
  중심으로 대충 찍지 않습니다 — 그러면 반경 밴드가 통째로 거짓이 됩니다.
- 무엇을 무엇으로 읽었는지 항상 찍습니다. 컬럼을 못 찾으면 실제 컬럼 목록을
  같이 찍어서, '자료가 없다' 와 '못 읽었다' 를 구분할 수 있게 합니다.

## 이 자료가 붙으면 달라지는 것

`hypotheses` 가 H1·H2 를 **H3 통제 전과 후로 나란히** 냅니다.

- 통제를 넣어도 IC 계수가 남으면 → IC 효과라고 부를 근거가 생깁니다.
- 통제를 넣자 사라지면 → 그건 산단·인구가 만든 것이었습니다. 그렇게 씁니다.

지금은 통제가 없어서, 어느 쪽인지 **말할 수 없는 상태**입니다.
