# Vercel 에 키를 두어도 되는가 — 점검 결과

결론부터: **지금 구조가 GitHub Actions 에 키를 두는 것보다 안전합니다.**
다만 점검 과정에서 실제 약점 세 가지를 찾아 고쳤습니다.

---

## 왜 더 안전한가

| | 이전 (Actions 에 키) | 지금 (Vercel 중계) |
|---|---|---|
| 키를 가진 곳 | GitHub Actions | Vercel 하나 |
| 워크플로 로그에 노출 | 마스킹에 의존 | **키가 아예 없음** |
| 유출 시 피해 | 인증키 자체 | 토큰만 — API 사용량 소모, 키는 안전 |
| 유출 시 복구 | 3개 재발급 | 토큰 한 개만 교체 |

Actions 에서는 이제 `REDT_RELAY_URL` 과 `REDT_RELAY_TOKEN` 만 씁니다.
**인증키는 러너 근처에 아예 오지 않습니다.**

---

## 키가 새어나갈 수 있는 경로 — 하나씩 확인

### 1. 정적 사이트에 섞여 들어가는가 → 아니오

`vercel.json` 의 `buildCommand`, `installCommand`, `framework` 가 모두 `null` 입니다.
**빌드 과정이 없으므로** 환경변수가 파일에 주입될 경로 자체가 없습니다.
(Next.js 처럼 빌드 시 `NEXT_PUBLIC_*` 을 번들에 넣는 구조가 아닙니다.)

`public/` 전체를 검색해 키 관련 문자열이 하나도 없음을 확인했습니다.

### 2. 브라우저에서 읽을 수 있는가 → 아니오

Vercel 환경변수는 **서버(함수) 안에서만** 보입니다.
`/api/relay` 는 서버에서 실행되고, 응답에 환경변수를 싣지 않습니다.

### 3. 상류 API 가 키를 되비추면 → **고쳤습니다**

일부 공공 API 는 오류 응답에 요청 URL 을 그대로 넣어 돌려줍니다.
그 URL 에는 우리가 끼워 넣은 인증키가 붙어 있습니다.

→ 응답을 돌려주기 전에 키 값을 `***` 로 치환합니다. 원본 인코딩·URL 인코딩 두 형태 모두.

### 4. 리디렉션으로 키가 딸려 나가는가 → **고쳤습니다**

`fetch` 는 기본적으로 리디렉션을 따라갑니다. 상류가 다른 호스트로 302 를 주면
**인증키가 붙은 요청이 그 호스트로 그대로 전달**됩니다.

→ `redirect: "manual"` 로 바꾸고, 3xx 가 오면 따라가지 않고 502 로 끊습니다.

### 5. 오류 메시지에 목적지 URL 이 들어가는가 → 아니오

중계기의 모든 오류 응답에서 `target` 을 제외했습니다. 그 URL 에는 키가 붙어 있습니다.

### 6. 토큰을 추측할 수 있는가 → **강화했습니다**

`!==` 비교는 일치하는 글자 수만큼 시간이 달라져 이론상 한 글자씩 알아낼 수 있습니다.

→ SHA-256 해시로 길이를 맞춘 뒤 `timingSafeEqual` 로 비교합니다.

### 7. 남이 우리 중계기를 자기 용도로 쓸 수 있는가 → 아니오

- `GET` 만 허용
- 토큰이 맞아야 함
- 목적지는 **세 호스트만** 허용 (`apis.data.go.kr`, `api.vworld.kr`, `data.ex.co.kr`)
- `https` 만 허용
- 호출측이 보낸 키 비슷한 파라미터는 전부 제거 후 우리 것으로 교체

### 8. Vercel 로그에 남는가 → 키는 남지 않음

중계기가 **받는** 요청에는 키가 없습니다 (호출측이 키를 모르므로).
중계기가 **보내는** 요청 URL 은 함수 내부에서만 존재하고, 로그로 출력하지 않습니다.

## 검증

가짜 상류 서버를 띄워 실제로 확인했습니다.

| 시나리오 | 결과 |
|---|---|
| 토큰 없음 / 빈 값 / 짧음 / 김 | 401 차단 |
| 허용 밖 호스트 (`evil.example.com`) | 403 차단 |
| `http://` 목적지 | 400 차단 |
| 상류가 오류 응답에 키를 되비춤 | `***` 로 치환, 나머지 내용은 보존 |
| 상류가 다른 호스트로 302 | 따라가지 않고 502 |
| 정상 호출 | 키 주입, 파라미터 보존, 응답 정상 파싱 |

## 남는 위험과 대응

**중계기 주소는 공개되어 있습니다.** `https://sado-toji.vercel.app/api/relay` 는
누구나 열 수 있고, 토큰이 유일한 자물쇠입니다.

- 토큰을 **30자 이상 무작위**로 만드세요. 짧거나 유추 가능하면 이 자물쇠가 약해집니다.
- 토큰이 샜다고 판단되면 Vercel 의 `RELAY_TOKEN` 과 GitHub 의 `REDT_RELAY_TOKEN` 을
  **같은 새 값으로** 바꾸고 재배포하면 끝입니다. 인증키는 그대로 둬도 됩니다.
- 토큰이 새더라도 공격자가 할 수 있는 최대치는 **대표님의 API 일일 사용량을 소모**하는 것입니다.
  인증키 자체는 얻을 수 없습니다 (중계기가 응답에서 지웁니다).

**Vercel 환경변수를 볼 수 있는 사람** — 프로젝트 소유자(대표님)뿐입니다.
팀원을 추가하지 않는 한 다른 사람은 볼 수 없습니다.
