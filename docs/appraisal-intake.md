# 감정평가서 받는 법 — '현재 가치' 의 원료

요구사항 2026-09-10. 필지 카드의 **현재 가치** 단추가 여기서 나온 값을 씁니다.

## 한 줄 요약

우리는 이미 **전국 모든 필지의 개별공시지가**를 갖고 있습니다. 모자란 것은
공시지가와 실제 값 사이의 **배율**입니다. 그 배율이 감정평가서마다 적혀
있습니다.

```
현재 가치 = 개별공시지가 × 예측배율
예측배율  = f(지역, 용도지역, 지구·구역, 지목, 도로접, 형상, 지세, 면적)
```

## 왜 실거래로는 안 되는가

실거래는 **팔린 땅**만 말합니다. 안 팔린 땅이 얼마인지는 말이 없습니다.
그런데 손님이 물어보는 땅은 대개 안 팔린 땅입니다. 감정평가서는
팔리지 않은 땅에도 값을 매긴 기록이라 그 빈칸을 메웁니다.

더 중요한 것은 **산식이 통째로 적혀 있다**는 점입니다 (감정평가에 관한
규칙 §14, 공시지가기준법).

```
토지가액 = 비교표준지 공시지가 × 시점수정 × 지역요인 × 개별요인 × 그 밖의 요인 보정
```

- **개별요인** — 가로 · 접근 · 환경 · 획지(면적/형상/지세) · 행정(용도지역/규제).
  요구사항에 적힌 칸이 여기 그대로 있습니다. 우리 다섯 축이 값을 얼마나
  가르는지를, **우리 추정이 아니라 평가사가 매긴 숫자**로 알게 됩니다.
- **그 밖의 요인 보정** — 공시지가와 시장가치가 벌어진 폭(대개 1.2~2.5배).
  지역마다 크게 다르고 **어디에도 공표되지 않습니다.** 이것이 이 서비스를
  남이 못 베끼는 지점입니다.

## 한 건에서 뽑아야 하는 것

표는 `src/redt/db.py` 의 `appraisal` · `appraisal_factor` 입니다.

### 필수 (이게 없으면 그 건은 못 씁니다)

| 칸 | 감정평가서에서 | 없으면 |
|---|---|---|
| `addr` | 소재지 | 필지를 못 찾음 |
| `area_m2` | 면적 | 단가를 못 냄 |
| `appraised_per_m2` | 단가 (원/㎡) | 학습 목표가 없음 |
| `official_price` | 대상 개별공시지가 | **배율을 못 냄** |
| `base_date` | 기준시점(가격시점) | 시점 보정을 못 함 |
| `land_use` | 용도지역 | 대입할 칸이 빔 |

`official_price` 가 평가서에 없으면 `addr` → PNU → 우리 `parcel` 표에서
채울 수 있습니다. 다만 **기준시점의 공시지가**여야 하므로 연도가 다르면
어긋납니다 — 평가서에 적힌 값이 있으면 그쪽이 낫습니다.

### 있으면 훨씬 좋은 것

`jimok` · `use_situation`(이용상황) · `road_side`(도로접면) · `shape`(형상) ·
`slope`(지세) · `zone_txt`(지구·구역 원문) · `std_pnu`/`std_price`(비교표준지) ·
`f_time`/`f_region`/`f_indiv`/`f_other`(산식 네 마디).

산식 네 마디가 다 있으면 **검산**이 됩니다 —
`std_price × f_time × f_region × f_indiv × f_other ≈ appraised_per_m2`.
안 맞는 건은 판독이 틀린 것이므로 조용히 버릴 수 있습니다. 이 검산이
없으면 잘못 읽은 건이 그대로 학습에 섞입니다.

### 개별요인 세부표 (`appraisal_factor`)

평가서 뒷쪽 '개별요인 비교' 표를 항목 단위로 옮깁니다.

```
group_nm  가로조건 / 접근조건 / 환경조건 / 획지조건 / 행정적조건 / 기타조건
item_nm   도로폭 · 형상 · 지세 · 면적 · 용도지역 …
subject   대상 토지의 값       comp  비교표준지의 값       ratio  격차율
```

## 원본을 두는 자리 — 구글 드라이브

```
드라이브 > 토지고고 감정평가서 /      ← 여기에 PDF 그대로
```

**처음에는 `data/raw/appraisal/` 이라고 적었는데 틀렸습니다.** 그것은
작업 컨테이너 안의 경로라 대화가 끝나면 사라지고, 폰으로 일하시는
분이 파일을 넣을 방법이 없습니다. 컴퓨터에서 작업하는 사람 기준으로
적은 안내였습니다.

구글 드라이브는 폰에서 바로 올릴 수 있고, 커넥터가 PDF 를 직접
읽습니다 (`read_file_content` 가 `application/pdf` 를 지원합니다).

**저장소에는 올리지 않습니다.** 감정평가서에는 소유자·채무자 이름이
적혀 있고 이 저장소는 공개입니다. 드라이브(개인 계정)에 두고 읽기만
합니다. 뽑아내는 것은 숫자와 조건뿐이라 `appraisal` 표에는 사람
이름이 들어가는 칸을 아예 만들지 않았습니다
(`scripts/test_privacy.py` 가 추적 파일을 봅니다).

**스캔 이미지 PDF 는 글자를 못 읽을 수 있습니다.** 첫 건을 열어 보고
바로 판단합니다 — OCR 을 붙이거나 다른 길을 찾아야 합니다.

## 몇 건이 필요한가

배율을 (지역 × 용도지역 × 도로접 × 형상) 로 가르려면, 칸 하나에 최소
열 건은 있어야 합니다.

| 건수 | 무엇까지 되는가 |
|---|---|
| 30~50 | 산식 판독기 만들기 · 검산이 맞는지 확인 |
| 200~300 | **시도 × 용도지역** 단위 배율. 첫 서비스는 여기서 시작 |
| 1,000+ | 시군구 단위 + 도로접·형상 격차율까지 |
| 3,000+ | 지구·구역(농업진흥·개발제한)별로 따로 |

한 지역에 몰리는 것보다 **여러 시도에 흩어진 것**이 낫습니다. 30건이
전부 안성이면 배울 수 있는 것은 안성의 배율 하나뿐입니다.

## 어디서 구하는가 — 확인이 필요한 부분

- **법원경매** (`courtauction.go.kr`) — 물건마다 감정평가서 PDF가 붙습니다.
  공개 자료지만 사이트가 자동 수집을 막습니다. 자동으로 받으려면 이용약관을
  먼저 확인해야 합니다. **직접 받아 폴더에 넣는 쪽이 확실합니다.**
- **온비드** (공매) — 공공데이터포털에 API가 있습니다. 감정평가서 원문까지
  주는지는 아직 확인 안 했습니다. 제공신청이 필요할 수 있습니다.
- **감정평가 정보체계 / 부동산공시가격 알리미** — 표준지 자료는 공개지만
  개별 평가서는 아닙니다.

## 다음 순서

1. **30~50건**을 드라이브의 '토지고고 감정평가서' 폴더에 올립니다
   (PDF 그대로). **한 건만 먼저 올려도 됩니다** — 서식을 봐야
   판독기를 제대로 만들고, 나머지를 올리기 전에 '이런 건 안 된다' 를
   미리 말씀드릴 수 있습니다.
2. 제가 한 건을 열어 보고 **판독기**를 만듭니다. 서식이 사무소마다 조금씩
   달라서, 실물을 보기 전에 만들면 헛짓이 됩니다.
3. 검산(`산식 곱 ≈ 평가액`)이 몇 %나 맞는지 보고합니다.
4. 맞으면 나머지를 다 읽고, 배율 회귀를 붙여 '현재 가치' 단추를 켭니다.
