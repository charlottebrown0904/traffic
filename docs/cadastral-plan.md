# B — 연속지적도로 지오코딩을 대체한다 (사전 준비)

사장님 지시(2026-09-08): "B를 위한 사전 준비내용 알려주고, 탐침해봅시다"

## 노리는 것

브이월드 지오코더는 하루 3만~4만 건입니다. **부르지 않고 계산하면**
그 한도가 사라집니다.

```
실거래 자료          →  법정동코드 + 지번  →  PNU  →  연속지적도 필지  →  중심 좌표
(우리가 이미 가짐)      (①이 필요)          (계산)   (②가 필요)         (공짜)
```

PNU 는 19자리이고 **계산으로 나옵니다.**

```
4155025300  1        0123     0004
법정동코드   산여부   본번     부번
   (10)      (1)      (4)      (4)          산여부: 일반 1 · 산 2
```

덤이 큽니다. 필지 도형이 함께 오므로 **면적과 모양**이 공짜로 붙습니다 —
필지 진단 레이더의 '모양·지세' 축 입력입니다. 지금은 이것을 브이월드
WFS(`dt_d194`)로 한 필지씩 받고 있고, 그것도 같은 한도를 씁니다.

---

## 준비물 넷

### ① 법정동 이름 → 코드 대조표  **(없으면 여기서 끝납니다)**

우리 실거래에는 법정동 **이름**만 있습니다. 코드가 없습니다.

```python
ALIASES = {
    "umd":        ["umdNm", "법정동"],     # ← 이름
    "jibun":      ["jibun", "지번"],
    "sigungu_cd": ["sggCd"],               # ← 5자리는 있다
}
```

PNU 앞 10자리를 만들려면 시군구(5) + 읍면동(3) + 리(2) 가 필요합니다.
가진 것은 앞 5자리뿐입니다. **뒤 5자리를 이름으로 찾아야 합니다.**

- 후보 1: 행정표준코드관리시스템(code.go.kr) 법정동코드 전체자료 — 무료 텍스트
- 후보 2: 브이월드 행정구역 WFS(`lt_c_ademd`) — 이름과 코드를 함께 줌

탐침 2절이 둘 다 두드립니다.

> **동명이인 문제가 있습니다.** 한 시군구 안에 같은 이름의 법정동은
> 없지만, 리까지 내려가면 표기가 흔들립니다("○○리" vs "○○리 산").
> 대조표를 받으면 우리 거래의 법정동 이름 중 **몇 %가 정확히 하나로
> 매칭되는지** 부터 셉니다. 여러 개에 걸리는 것은 버립니다 —
> 틀린 PNU 는 엉뚱한 필지를 가리키고, 그건 좌표가 없는 것보다 나쁩니다.

### ② 연속지적도를 통째로 받는 길

이게 서야 호출이 0 이 됩니다. API 로 한 필지씩이면 결국 같은 한도에
다시 묶입니다.

- 후보 1: 공공데이터포털 파일데이터 "연속지적도형정보"
- 후보 2: 국가공간정보포털(nsdi.go.kr) 오픈마켓
- 후보 3: 브이월드 WFS `lp_pa_cbnd_bubun` / `lp_pa_cbnd_bonbun`
  (한 필지씩 — 절충안)

탐침 3·4절이 확인합니다.

> ⚠️ nsdi.go.kr 은 우리 **중계기 허용목록에 없습니다.** 미국 러너에서
> 직접 나가므로 지오블록에 막힐 수 있습니다. 막히면 그것도 결과입니다 —
> `api/relay.js` 의 ALLOW 와 `http.py` 의 RELAYED_HOSTS 양쪽에 넣으면
> 됩니다. 한쪽만 넣으면 조용히 직접 나가서 막힙니다.

### ③ 지번 문자열이 실제로 파싱되는가

`123-4` · `산 45` · `123` 세 모양을 예상하지만, 실제 값을 안 보고
정규식을 짜면 조용히 깨집니다. 탐침 1절이 표본 12건의 원문과
**전국 파싱률**을 찍습니다. 파싱 안 되는 것은 PNU 를 안 만듭니다.

### ④ 용량 — 이게 진짜 제약입니다

전국 필지는 약 3,800만 개입니다. 원본 도형을 다 들고 있을 수 없습니다.

```
Actions 캐시 한도      10 GB
현재 사용              6.23 GB (62%)
한 실행의 캐시          2.03 GB
남는 여유              약 1.7 GB
```

**끝까지 들고 있을 필요가 없습니다.** 시군구 하나씩 받아 필요한 것만
남기고 원본은 그 자리에서 버립니다.

```
PNU(19) + 위도 + 경도 + 면적 + 둘레   ≈ 40 B/필지
거래가 있는 필지만 (약 330만)          ≈ 130 MB
전국 3,800만 필지 전부                 ≈ 1.5 GB   ← 여유를 다 씁니다
```

→ **거래가 있는 필지만 남깁니다.** 나중에 필요하면 그때 넓힙니다.

## 탐침이 답할 것

```
1절 파싱률이 낮으면       → 지번 정규식을 고친다
2절이 다 막히면           → PNU 를 못 만든다. B 는 여기서 끝난다
3절만 되고 4절이 막히면   → 호출 0 은 못 한다. 한도 안에서 도형만 얻는 절충
4절이 되면                → 지오코딩 병목이 사라진다
```

돌리는 법 — GitHub → Actions → 수집 → Run workflow

```
stage : web            (캐시만 복원하고 탐침만 돈다 — 약 4분)
probe : cadastral
```

수집을 건드리지 않고 읽기만 하므로 아무 때나 켜도 안전합니다.

---

## 탐침 뒤에 할 일 (B 가 서면)

1. 법정동 대조표를 `config/` 에 받아 두고 매칭률을 잰다
2. `PNU → (lat, lon, area, 둘레)` 표를 시군구 단위로 만든다
3. 좌표가 법정동 중심점인 거래를 이 표로 **덮어쓴다**
   — 캐시의 `level` 을 `parcel` 로 올린다
4. 브이월드 지오코더는 **표에 없는 필지만** 부른다 (보조로 강등)
5. 면적·모양을 레이더의 '모양·지세' 축에 연결한다

## 하지 않을 것

- **키 여러 개로 한도 우회.** 브이월드 이용약관 위반입니다.
- **다른 지오코더 섞기.** 대표점 규칙이 달라 같은 필지가 지오코더마다
  다른 점으로 찍힙니다. 거리 밴드 분석에 잡음으로 들어옵니다.
