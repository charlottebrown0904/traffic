# 브이월드 지오코더 일일 한도 상향 신청서 — 입력값

요구사항(2026-09-08): "A 를 위한 신청서 만들어 주고 당 서비스에서
지오코딩이 필요한 내용, 사용자의 편의를 위한 새로운 항목 추가 위주"

브이월드 → 로그인 → `오픈API` → `인증키 관리` → 해당 키 → **한도 증설/문의**

> 화면 문구는 브이월드가 종종 바꿉니다. "트래픽 증설", "일일 요청 한도
> 상향", "1:1 문의" 중 무엇으로 적혀 있든 **사유를 적어 내는 그 칸**입니다.
> 신청 창구가 안 보이면 고객센터 1:1 문의로 아래 내용을 그대로 보내십시오.

---

## 요청 한도

```
현재 : 일 30,000건
요청 : 일 100,000건
```

> **근거를 숫자로 대는 것이 이 신청의 전부입니다.** 아래 §2 가 그
> 숫자를 만듭니다. "많이 필요합니다" 는 심사에서 통과하지 않습니다.

---

## 1. 서비스 개요

```
서비스명 : 토지 고고 (https://toji.fyi)
성격     : 전국 토지 실거래가를 지도에서 비교하고, 개별 필지를 눌러
           개발 방향을 진단하는 웹 서비스. 비영리 연구 단계.

국토교통부 실거래가 공개시스템의 토지·공장 거래 1,179만 건과
한국도로공사의 영업소별 차종 교통량을 결합해, "이 땅이 얼마인가" 가
아니라 "이 땅을 어느 방향으로 쓰는 것이 맞는가" 를 보여줍니다.
```

## 2. 지오코딩이 왜 필요한가 — 숫자로

```
국토교통부 실거래가 자료에는 좌표가 없습니다. 시군구·법정동·지번의
문자열만 옵니다. 좌표가 없으면 이 서비스는 성립하지 않습니다 —
지도에 찍을 수도, 고속도로 IC 로부터의 거리를 잴 수도 없습니다.

  적재한 실거래 전체              11,793,406 건
  좌표가 붙은 것                  11,409,686 건 (96.7%)

숫자만 보면 다 된 것 같지만 아닙니다. 붙은 좌표의 대부분이
**법정동 중심점**입니다 — 오차가 ±1~2km 라, 그 동네 안 어디쯤이라는
뜻이지 그 필지가 아닙니다. 거리 밴드도, 도로 접함도, 주변 필지 비교도
이 좌표로는 말할 수 없습니다.

  필지(지번) 단위          [탐침 결과로 채웁니다] 건
  법정동 중심점 단위        [탐침 결과로 채웁니다] 건  ← 올려야 할 양
  좌표 없음                 [탐침 결과로 채웁니다] 건

  현재 한도(일 30,000)로 처리하면    [일수]
  요청 한도(일 100,000)로는          [일수]

호출을 줄이는 설계는 이미 적용했습니다.
  · 1단계 법정동 중심점을 먼저 붙여 같은 동네를 반복 호출하지 않음
  · 2단계 분석 대상 반경 안에 드는 거래만 지번 단위로 승격
  · 결과를 영구 캐시. 같은 주소를 두 번 묻지 않음
  · 한도 초과 응답을 '주소 없음' 과 구분해 캐시에 잘못 박히지 않게 함

이 설계 없이는 필요량이 몇 배였습니다. 줄일 만큼 줄인 뒤의 숫자입니다.
```

> **대괄호 칸은 아직 비어 있습니다.** 실측하지 않은 숫자를 신청서에
> 적으면, 심사자가 한 번 확인해 보고 틀린 것을 발견하는 순간 나머지도
> 안 믿습니다. `probe: cadastral` 탐침이 이 숫자를 찍어 오면 채웁니다.

## 3. 상향분으로 새로 여는 기능 — 이용자 편의

```
(1) 필지 진단 레이더
    지도에서 필지를 누르면 다섯 축(도로 접함·교통 접근성·개발 여지·
    가격 수준·모양과 지세)을 같은 용도지역 이웃들과 견준 그림으로
    보여줍니다. 일반 이용자는 "계획관리 1,650㎡, 세로한면(가), 평지"
    라는 말을 읽어도 그것이 좋은지 나쁜지 알 수 없습니다. 주변
    필지들 사이에서 어디쯤인지를 보여주면 그때 읽힙니다.
    → 필지 단위 좌표가 있어야 '주변 필지'를 고를 수 있습니다.

(2) 내 땅 주소로 바로 찾기
    지금은 지도를 확대해 눈으로 찾아야 합니다. 주소를 입력해 곧바로
    그 필지로 가는 검색을 붙입니다. 이용자 한 사람의 검색 한 번이
    지오코딩 호출 한 번입니다.

(3) 주변 최근 실거래 붙이기
    필지를 눌렀을 때 반경 안의 최근 거래를 함께 보여줍니다.
    반경 계산은 양쪽 다 필지 단위 좌표를 요구합니다.

(4) 읍·면·동, 리 단위 시세
    지금은 시·군·구까지만 정확합니다. 같은 군 안에서도 면마다 값이
    몇 배 차이 나는데, 그 차이가 안 보이면 시세를 잘못 읽습니다.
```

## 4. 공익성

```
· 토지 가격 정보는 지역·물건별로 흩어져 있어 일반인이 비교하기
  어렵습니다. 공공이 이미 공개한 자료(실거래가·공시지가·교통량)를
  한 화면에서 견줄 수 있게 하는 것이 목적입니다.
· 분석 결과는 투자 권유가 아니라 참고 정보로 제공하며, 그 취지를
  화면에 명시하고 있습니다.
· 표본이 적은 구간은 값을 내지 않고 '자료 부족' 으로 표시합니다
  (거래 5건 미만 구간은 비웁니다). 적은 표본으로 만든 숫자가
  돌아다니는 것이 정보가 없는 것보다 나쁘다고 보기 때문입니다.
· 어떤 자료를 어떻게 썼는지는 저장소에 공개돼 있습니다.
  https://github.com/charlottebrown0904/traffic
```

## 5. 호출 방식 (심사자가 궁금해할 것)

```
· 지오코더 API 를 서버에서 배치로 호출합니다. 이용자 요청 하나가
  API 호출 하나로 곧바로 나가지 않습니다.
· 결과는 영구 저장하며 같은 주소를 다시 묻지 않습니다.
· 초당 12건 상한을 코드에 걸어 두었습니다. 총량이 늘어도 순간
  부하를 만들지 않습니다.
· 한도 초과 응답(OVER_REQUEST_LIMIT)을 받으면 그 자리에서 멈추고
  다음 날 이어받습니다. 재시도로 두드리지 않습니다.
· 등록 서비스URL : https://toji.fyi
```

## 붙임 — 신청 뒤

- 승인 여부와 상향 폭은 심사 재량입니다. **얼마를 올려주는지 공개된
  표를 본 적이 없습니다.** 안 되면 B(연속지적도)로 갑니다.
- 상향되면 `collect.yml` 의 `geocode_limit` 기본값을 그 숫자로 올립니다.
  지금은 30,000 입니다.
- 한도에 걸리면 우리 코드가 **몇 건째에서 걸렸는지 찍습니다.**
  그 숫자가 곧 실측값이니, 상향 뒤 첫 실행 로그를 확인하면 됩니다.
