# 대안 축 — 공시지가 (대표님 지시 3번, 착수 전)

실거래 표본이 끝내 얇으면 **가격 축을 공시지가로 갈아끼운다.**
아직 착수하지 않았고, 이 문서는 착수 시점에 헤매지 않기 위한 정리다.

## 왜 유효한 대안인가

실거래는 **그 해에 팔린 땅만** 보인다. 안 팔리면 관측 자체가 없다. 그래서
셀당 최소 거래건수 조건에서 대부분의 칸이 떨어져 나간다.

공시지가는 **모든 필지에 매년 매겨진다.** 표본 문제가 원천적으로 없다.
영업소 하나에 붙는 필지가 수백 개고, 매년 값이 있으므로 밴드×연도 셀이
비지 않는다.

## 대신 이런 한계가 있다

- **실거래가 아니라 평가액이다.** 시세 반응이 한 박자 늦다. 교통량이 오른
  해에 바로 반응하지 않고 이듬해 공시에 반영될 수 있다. 시차를 1년이 아니라
  1~2년으로 놓고 둘 다 봐야 한다.
- **평가 자체가 인근 실거래를 참고한다.** 가격이 오른 곳을 평가가 따라간
  것인지, 우리가 보려는 인과인지 구분이 흐려진다.
- 결론을 낼 때 "실거래 기준" 인지 "공시지가 기준" 인지 반드시 밝혀야 한다.
  둘을 섞어 말하면 투자자에게 잘못된 인상을 준다.

## 두 갈래 원천

| | 표준지 | 개별 |
|---|---|---|
| 대상 | 전국 약 50만 필지 (대표 표본) | 전 필지 (약 3,900만) |
| 성격 | 감정평가사가 직접 평가 | 표준지를 기준으로 산정 |
| 양 | 다루기 쉬움 | 매우 큼 |
| 데이터셋 | [15004246 표준지공시지가](https://www.data.go.kr/data/15004246/fileData.do) (SHP·CSV 파일) | [15029071 전국개별공시지가 표준데이터](https://www.data.go.kr/data/15029071/standard.do) |

**표준지부터 시작한다.** 50만 필지면 밴드별 표본이 충분하고, 평가 방식이
전국에서 일관돼 연도 간 비교가 깨끗하다. 개별공시지가는 필지 수가 너무 많아
지오코딩·공간조인 비용이 크고, 표준지를 기준으로 파생된 값이라 정보가
겹친다.

## 어디서 받아오는가 (2026-09-01 확인)

대표님이 개발계정을 승인받으셨습니다. 그래서 파일이 아니라 **API** 로
갑니다. 다만 그 API 가 어디 있는지 찾는 데 몇 번을 헛짚었고, 그 경위를
남깁니다. 같은 함정이 다음에도 있습니다.

### 헛짚은 길

`apis.data.go.kr/1611000/nsdi/...` 아래에 있을 것으로 보고 서비스 이름
후보 30개를 실제로 불러봤습니다. **전부 HTTP 400** 이었습니다. 이름을
더 잘 추측해서 될 일이 아니었습니다 — **주소가 그 도메인에 애초에
없었습니다.**

### 실제 경로

포털 페이지를 읽으니 답이 있었습니다.

| | |
|---|---|
| 데이터셋 | **15123971** 국토교통부_표준지공시지가정보(WMS/WFS/속성정보) |
| 성격 | **링크 API** — 포털이 직접 서비스하지 않고 제공처로 넘긴다 |
| 제공처 | **브이월드 (VWorld)** |
| 설명 | "공시지가정보와 **연속지적도를 융복합**하여 생성한 **공간정보** 데이터" |

제공처 주소는 페이지의 바로가기 버튼이 쓰는 조회로 확인했습니다.

```
GET www.data.go.kr/tcs/dss/selectApiLinkUrl.do?publicDataPk=15123971
→ {"linkUrl":"https://www.vworld.kr/dtna/dtna_apiSvcList_s001.do?...","status":true}
```

### 제공되는 기능 (브이월드 목록에서 확인)

| 기능 | 내용 |
|---|---|
| 표준지공시지가WMS조회 | 맵 이미지 |
| **표준지공시지가WFS조회** | **도형 및 속성값을 포함한 피처 집합** ← 우리가 쓸 것 |
| 표준지공시지가속성조회 | 속성만 |

WFS 가 도형을 함께 준다고 명시돼 있습니다. **좌표가 온다는 뜻이고,
지오코딩 단계가 통째로 사라집니다.** 지금 실거래 쪽에서 하루 4,000건
한도로 며칠씩 잡아먹는 그 단계입니다.

### 우리에게 유리한 점

브이월드는 이미 쓰고 있는 곳입니다. `api.vworld.kr` 이 중계기 화이트
리스트에 있고 `VWORLD_KEY` 도 이미 들어가 있습니다. 지오코딩에 쓰던
바로 그 경로라 새로 뚫을 것이 없습니다.

### 아직 모르는 것 — 레이어 이름

WFS 를 부르려면 레이어 이름(`data=` 값)이 필요한데, 그것은 기능별 상세
페이지에 있고 그 페이지가 자바스크립트로 그려집니다. 긁어서는 못 뽑았고,
**모르는 것을 추측해 적어두지 않습니다.**

받는 방법은 둘 중 하나입니다.

1. 대표님이 브이월드 오픈API 문서에서 '표준지공시지가WFS조회' 를 열어
   요청 예시 한 줄을 주신다. 거기에 `data=` 값이 적혀 있습니다.
2. 브이월드 데이터 목록 API 로 레이어 목록을 받아 이름에 '공시지가' 가
   들어간 것을 고른다. 이쪽은 추가 작업이 필요합니다.

### 막혔다가 뚫린 곳 — Referer

WFS 를 부르니 `INCORRECT_KEY` 가 왔습니다. 저는 이것을 '키에 WFS 권한이
없다' 로 읽고 대표님께 권한을 켜달라고 말씀드렸는데, **틀렸습니다.**
대표님이 보여주신 화면에 WMS/WFS API 는 이미 신청돼 있었습니다.

진짜 원인은 다른 데 있었습니다. 이 키는 '웹사이트' 유형이고 서비스URL 이
`https://sado-toji.vercel.app/` 로 등록돼 있습니다. 브이월드는 WMS/WFS 에서
요청이 그 도메인에서 왔는지를 **Referer** 로 봅니다. 중계기는 브라우저가
아니라 서버라 Referer 를 붙이지 않았습니다.

지오코더는 이것을 따지지 않습니다. 그래서 같은 키로 지오코더는 `OK`,
WFS 는 `INCORRECT_KEY` 라는 엇갈린 결과가 나왔고, 저는 흔한 쪽 원인을
골랐습니다. 증상 하나에 원인이 둘일 때 더 흔한 쪽을 고르는 것은
합리적이지만, 그것을 확인 전에 대표님께 조치 사항으로 말씀드린 것은
성급했습니다.

중계기가 브이월드로 갈 때 등록된 주소를 Referer 로 싣게 고쳤습니다.
`VWORLD_REFERER` 로 덮어쓸 수 있고 기본값은 지금 등록된 서비스URL 입니다.

### 그다음 — 일반 WFS 에는 공시지가가 없다

Referer 를 실으니 WFS 가 열려 레이어 **177개**가 왔습니다. 그런데 그 안에
공시지가가 없습니다. '지가·표준지·가격·토지·지목·필지' 로 훑어도
`lt_c_lhblpn`(토지이용계획도)과 `dt_d160`(토지소유공간정보) 둘뿐입니다.

대표님 화면의 활용API 목록에 **'국가중점 API'** 가 따로 있는 것이
단서였습니다. 공시지가는 국가중점데이터라 브이월드가 **`/ned`** 아래
별도 경로로 서비스합니다. 일반 WFS 를 뒤져서는 나올 수 없었습니다.

### `/ned` 에서 갈린 것

응답이 두 갈래로 갈립니다. 이 차이가 이름이 맞는지를 알려줍니다.

| 오퍼레이션 | 응답 | 뜻 |
|---|---|---|
| `getStdrLandPriceWFS` | `URL_TYPE 잘못된 URL 입니다` | 그런 이름이 없다 |
| `getStandardLandPriceWFS` | 〃 | 〃 |
| `getStdLandPriceWFS` | 〃 | 〃 |
| **`getIndvdLandPriceWFS`** | HTTP 500 | **이름은 안다** — 인자에서 걸렸다 |
| **`getLandCharacteristicsWFS`** | HTTP 500 | **이름은 안다** |

500 은 실패지만 '그런 오퍼레이션이 없다' 와는 다릅니다. 서버가 이름을
알아듣고 처리하다 걸린 것입니다.

**개별공시지가(`IndvdLandPrice`)와 토지특성(`LandCharacteristics`)은
이름이 맞습니다.** 표준지는 아직 못 찾았습니다.

이건 오히려 잘된 쪽일 수 있습니다. 앞서 개별공시지가를 '좌표가 없어
지오코딩을 다시 타야 한다' 는 이유로 밀어뒀는데, **WFS 로 오면 도형이
함께 옵니다.** 그 이유가 사라집니다. 게다가 필지 수는 표준지(50만)보다
개별(3,900만)이 훨씬 많아 밴드×연도 셀이 빌 일이 없습니다.
토지특성에는 용도지역이 들어 있을 수 있어 계획관리·생산관리·자연녹지
필터를 그대로 쓸 수 있습니다 — 확인이 필요합니다.

남은 일은 인자를 맞추는 것입니다. 이름을 찾는 것보다 훨씬 쉽습니다.

## 실제로 받아본 결과 (2026-09-01)

### 되는 호출

```
GET https://api.vworld.kr/ned/wfs/getLandCharacteristicsWFS
    ?key=...&domain=sado-toji.vercel.app
    &typename=dt_d194
    &bbox=126.87,37.06,126.93,37.11
    &srsName=EPSG:4326
    &output=application/json      ← 이것이 결정적
    &maxFeatures=3&resultType=results
```

`output=application/json` 이 갈랐습니다. GML·XML 로 요청하면 중계기가
`FUNCTION_INVOCATION_FAILED` 로 죽습니다. typename 은 서버가 오류 메시지로
직접 알려줬습니다 — `dt_d150`(개별공시지가), `dt_d194`(토지특성).

### 한 번 호출에 다 들어 있다 (토지특성)

| 필드 | 값 | 쓸 곳 |
|---|---|---|
| `pblntf_pclnd` | 272000 | 공시지가 원/㎡ — **가격 축** |
| `prpos_area_1_nm` | 계획관리지역 | **용도지역 필터 그대로** |
| `lndcgr_code_nm` | 공장용지 | 지목 |
| `lad_use_sittn_nm` | 공업용 | 토지이용상황 |
| `lndpcl_ar` | 3840 | 면적 |
| `geometry` | 있음 | **지오코딩 불필요** |
| `pnu` | 4122025923100080085 | 필지 식별자 |

### 그러나 — WFS 는 연도를 무시한다 (확인됨)

`stdrYear` 를 받아들이는 척하고 무시합니다.

| 요청 | 응답 `stdr_year` | 값 |
|---|---|---|
| 2018 | 2026 | 272000 |
| 2020 | 2026 | 272000 |
| 2022 | 2026 | 272000 |
| 2024 | 2026 | 272000 |
| 2025 | 2026 | 272000 |

같은 필지 세 곳을 다섯 해에 걸쳐 확인했고 전부 같은 값이었습니다.

**건수만 셌다면 못 잡았습니다.** `maxFeatures=3` 이라 어느 해나 3건이
옵니다. "연도별 전부 3건" 을 보고 '된다' 고 적었다면, 같은 해 자료에
다른 연도 딱지를 붙여 변화량 회귀에 넣었을 것입니다. 지금까지 우리를
여섯 번 문 것과 정확히 같은 형태입니다.

### 속성 조회는 연도별을 주지만 — 두세 해뿐이다

`/ned/data/getIndvdLandPriceAttr` 는 WFS 와 달리 `stdrYear` 를 제대로
받고 값도 해마다 다릅니다. 그런데 **있는 해가 두세 개뿐**입니다.

| 필지 | 확보 연도 |
|---|---|
| 4122025923100080085 (평택) | 2024 · 2025 · 2026 |
| 4159134036200190003 (화성) | 2025 · 2026 |
| 4159134036200210001 (화성) | 2025 · 2026 |
| 4159134036100350003 (화성) | 2025 · 2026 |

2010~2023 은 전부 0건입니다.

처음 한 필지만 봤을 때는 '그 필지가 2024년에 신설됐을 수도 있다' 고
의심했는데, 다른 곳도 마찬가지였습니다. **필지 사정이 아니라 API 가
최근 몇 해만 들고 있는 것입니다.**

두세 해로는 연도 고정효과를 넣은 패널 회귀에 들어갈 수 없습니다.
차분을 한 번 내면 한두 해가 남습니다.

### 그래서 지금 서 있는 자리

| | 상태 |
|---|---|
| 필지 목록·좌표·용도지역·지목·면적 | **해결** — WFS `dt_d194`, 지오코딩 불필요 |
| 가격 **시계열** | **막힘** — 브이월드 API 는 두세 해뿐 |

좌표 문제가 풀린 것은 그대로 남습니다. PNU 를 키로 두면 **좌표는
브이월드에서, 가격 시계열은 다른 원천에서** 받아 붙일 수 있습니다.
지오코딩은 여전히 필요 없습니다.

남은 원천 후보는 둘입니다.

1. **전국개별공시지가 표준데이터 (15029071)** — `api.odcloud.kr`.
   좌표는 없지만 PNU 가 있어 브이월드 좌표와 붙일 수 있습니다. 연도별로
   있는지 확인해야 합니다. 중계기에 이미 열려 있어 확인 비용이 낮습니다.
2. **표준지공시지가 파일 (15004246)** — 연도마다 파일이 따로 있습니다.
   대표님이 내려받아 올려주셔야 하고, 20년치면 파일 20개입니다.

## 그 밖에 바로잡은 것

- 앞서 "파일(15004246 SHP)로 가야 한다" 고 적었던 것은 **틀렸습니다.**
  API 경로가 있고, 그쪽이 더 낫습니다.
- "api.odcloud.kr 을 쓰려면 RELAYED_HOSTS 를 손대야 한다" 도 **틀렸습니다.**
  중계기에 이미 들어 있었습니다. 제 컨테이너에서 막힌 것을 중계기에서도
  막힌 것으로 넘겨짚었습니다.
- "브이월드 키에 WFS 권한이 없다" 도 **틀렸습니다.** 권한은 있었고 Referer
  문제였습니다. 확인 전에 대표님께 조치를 요청한 것이 성급했습니다.
- "개별공시지가는 좌표가 없어 쓸 수 없다" 도 **틀렸습니다.** 속성 API 만
  보고 판단했는데, WFS 로 부르면 도형이 함께 옵니다.

세 번 다 같은 형태의 잘못입니다. 한쪽에서 본 사실을 다른 쪽에도
그대로 적용했습니다. 확인 비용이 낮은 것은 넘겨짚지 말고 불러봐야
합니다.

## 저장소를 공개로 바꾸기 전에 (2026-09-01)

Actions 분을 아끼려 저장소 공개를 검토했으나, **동시 요청으로 수집
시간이 줄면 공개할 이유가 없어져** 보류했습니다. 되돌릴 수 없는 선택을
되돌릴 수 있는 선택보다 먼저 쓰지 않기로 했습니다.

**나중에라도 공개로 바꾸신다면 그 전에 반드시:**

# 용도지역을 지도에 깔 최적 경로 (2026-09-03 탐침)

`scripts/vworld_layers.py zoning` 으로 서버에 직접 물었습니다.
결과가 제 추측을 **세 겹으로** 깼습니다.

## 틀렸던 것

`api/tile.js` 에 `LT_C_UQ111` 을 WMTS 로 부르게 박아 넣었습니다. 그
이름은 저장소 어디에도 근거가 없는 추측이었습니다.

| 추측 | 실제 |
|---|---|
| WMTS 로 받는다 | 캐패빌리티·타일 **전부 404** — 못 받습니다 |
| `LT_C_UQ111` | 대문자는 `text/xml` 오류. **소문자만** 받습니다 |
| 그 한 장이 '용도지역' | 그것은 **'도시지역'** 입니다. 용도지역은 넷입니다 |

세 번째가 가장 위험했습니다. 우리 필터는 계획관리·생산관리·자연녹지고,
**계획관리와 생산관리는 `lt_c_uq112`(관리지역)** 에 있습니다. 제가 박아
넣은 `uq111` 만 깔면 정작 우리가 보는 땅이 지도에서 통째로 빕니다.

```
lt_c_uq111  도시지역          ← 자연녹지가 이 안
lt_c_uq112  관리지역          ← 계획관리·생산관리가 이 안
lt_c_uq113  농림지역
lt_c_uq114  자연환경보전지역
```

`lt_c_lhblpn`(토지이용계획도)도 한때 유력했지만 아니었습니다. WFS 로
받아 보니 `zonename` 이 **"화성향남2지구 택지개발사업 (3단계)"** 였습니다
— 용도지역이 아니라 개발사업 지구입니다. 13KB 로 얇았던 것도 그래서입니다
(`uq112` 는 39KB).

## 확정된 것

| 항목 | 결과 |
|---|---|
| WMS GetMap | `lt_c_uq111` 33,064B PNG · `lt_c_uq112` 39,789B PNG |
| `LAYERS` 쉼표 | **네 장을 한 요청에 겹쳐 줍니다** — 55,190B PNG |
| EPSG:3857 | `CRS` 로 보내면 옵니다. `SRS` 는 빈 그림 |
| 필지 경계선 | `lp_pa_cbnd_bubun` (연속지적도) |
| 점 조회 | `GetFeatureInfo` 로 누른 점의 용도지역을 받습니다 |

`SRS` 함정은 크기가 단서였습니다. 레이어를 바꿔도 **똑같이 1,784B** 가
왔습니다 — 서로 다른 땅이 같은 바이트일 수 없습니다. `SRS` 는 WMS
1.1.1 것이고 1.3.0 은 `CRS` 를 씁니다. 오류를 내지 않고 빈 그림을 주므로
크기를 안 봤으면 '된다' 고 적었을 것입니다.

## 그래서 고른 방법

**WMS GetMap · 네 장 한 번에 · EPSG:3857 · 우리 서버 경유** (`api/tile.js`).

```
GET /api/tile?layer=zoning&z=13&y=3186&x=6983
  → LAYERS=lt_c_uq111,lt_c_uq112,lt_c_uq113,lt_c_uq114
    CRS=EPSG:3857  BBOX=<타일의 머케이터 범위>  256×256 PNG
```

- **브이월드 공식 색** 이라 지적편집도를 읽어온 분들에게 설명이 필요 없습니다
- **타일 한 장에 요청 한 번** — 네 장을 따로 받으면 네 배입니다
- **키가 브라우저에 안 나갑니다** — 서버가 대신 받아옵니다
- 주소가 `z/x/y` 로 고정되므로 **Vercel CDN 이 반복 요청을 대신 받습니다**.
  bbox 를 그대로 받으면 주소가 매번 달라 캐시가 안 걸립니다.
- 배율 12부터 색면, 15부터 필지선. 전국 배율에서 색면을 깔면 지도를
  통째로 덮어 거래 점도 영업소도 안 보입니다.

## 다음에 쓸 수 있는 것

`GetFeatureInfo` 가 됩니다. 필지를 눌렀을 때 **도형을 다 받아오지 않고**
그 점의 용도지역만 물어볼 수 있습니다. 실거래 점을 눌러 '이 땅은
계획관리지역' 을 띄우는 데 쓸 수 있고, 호출 한 번이라 쌉니다.

주의 — 한 레이어만 물으면 그 레이어에 안 걸리는 점은 `features: []` 로
옵니다(오류가 아닙니다). 네 장을 함께 물어야 어느 용도지역인지 답이 옵니다.
