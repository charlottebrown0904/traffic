## 1. 방향 — 행이 표준지, 열이 대상, 값은 곱한다

파일에는 방향이 적혀 있지 않습니다. 표 하나로 확정됩니다.

```
도로접면    행 '맹지'    × 열 '광대한면'  = 1.37
            행 '광대한면' × 열 '맹지'      = 0.73    (≒ 1/1.37)
```

맹지가 광대한면보다 비쌀 수는 없습니다. 그러므로

> **행 = 비교표준지, 열 = 산정 대상 토지, 값 = 곱하는 배율**
> 대상 단가 = 표준지 단가 × 표(표준지 항목, 대상 항목)

행을 대상으로 읽으면 맹지가 광대한면의 1.37배가 되어 버립니다. 다른
항목에서도 같습니다 — 토지이용상황 행'임야'×열'주거용' = 2.04,
행'주거용'×열'임야' = 0.49. 공공용지 행'일반'×열'도로' = 0.33.
전부 뒤집으면 말이 되지 않습니다. 방향은 하나로 정해집니다.

행렬은 대체로 **역수 대칭**입니다(1/2.04 = 0.49). 기준이 되는 특성이
1.00 인 대각선을 가지므로, 표준지를 어떤 특성으로 잡아도 같은 답이
나옵니다.

    10~13pp 높고, 원삼면은 광대·소로가 우리와 정확히 같습니다. 우리 값이
    평가서 40건에서 나온 값이라는 점과 맞물려, **도로접면은 그대로
    둔다**는 §5-1 의 결정이 더 단단해졌습니다. 어느 한 읍·면 표를 "관의
    정답"으로 옮겨 적었다면 다른 읍·면과 10pp 어긋났을 것입니다.
  · **고저는 보개면 값을 그대로 둡니다.** 원삼면은 완경사·급경사·고지가
    3pp 안이고 저지만 9pp 낮습니다(0.88). 저지 사례가 원장에 거의 없어
    어느 쪽이 맞는지 검산할 수 없고, 한 장을 근거로 바꿀 이유가 못 됩니다.
    저지 사례가 쌓이면 다시 봅니다. `valuation.py SLOPE_INDEX` 주석에도
    적어 두었습니다.
  · **특례 세 값(0.33 · 0.85 · 0.60)은 세 곳 모두 같습니다.** 이건
    읍·면을 넘어 전국이 같은 값을 쓰는 항목으로 보입니다 — 우리 `SPECIAL`
    이 관의 값과 일치한다는 §3 의 확인이 두 번째 지역에서도 섭니다.
  · **이용상황 전→임야가 0.49 vs 0.74** — 같은 경기도 안에서 25pp 차이.
    보개면(안성) 임야가 농지에 비해 훨씬 싸다는 뜻입니다. 우리
    `USE_MISMATCH` (임야, 전·답) = 0.80 은 원삼면 쪽에 가깝습니다. 이
    값은 지역 격차가 커서 하나로 못 두는 항목이라는 것을 기억해 둡니다.

### 7-3. 코드에 바뀐 것

  · `valuation.bijunpyo_files()` — `data/bijunpyo/*.tsv` 전부, 보개면이 맨 앞.
  · `valuation.bijunpyo_index(zone, path)` — 지역·연도를 **파일 안(sgg_nm·year
    열)에서** 읽고, 형상의 기준 행을 정방형 → 정형 순으로 찾습니다(원삼면은
    2×2 라 정방형 행이 없습니다).
  · `valuation.bijunpyo_regions()` → `valuation.json` 의 `bijunpyo_regions`
    (목록). 옛 `bijunpyo`(보개면 한 장)도 그대로 실어 옛 화면이 깨지지 않습니다.
  · Admin 격차율 표 — 대상 | 우리 값 | 보개면 2026 | 원삼면 2026 한 표.
  · `scripts/test_valuation.py` §1-2 — 파일 2개 이상, 보개면이 앞, 원삼면
    광대한면 = 1.25 = 우리 값.
  · 새 읍·면 표가 오면 `scripts/parse_bijunpyo.py <파일> --sgg <코드> --sgg-name
    "<시군구> <읍면>" --year <연도> --out data/bijunpyo/<코드>_<읍면>_<연도>.tsv`
    한 줄로 화면에 열이 하나 늘어납니다.
