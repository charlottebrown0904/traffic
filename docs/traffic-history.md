# 교통량 과거 시계열 확보 경로

## 확보 완료 (2026-09-02)

**2003~2025년 23년치를 다 받았습니다.** 목표한 구간이 채워졌습니다.

| | |
|---|---|
| 교통량 | 2003-01 ~ 2025-12 · **274개월** |
| 결측 | 2004-06 · 2010-10 (2개월) |
| 파일 | `data/raw/tcs_annual_2003.csv` … `tcs_annual_2025.csv` (+ `tcs_monthly_*`) |
| 영업소 | 개통 확인 252 · 좌측절단 231 · 폐쇄 확인 9 |

### 결측 두 달

- **2010-10** 포털에 원본이 없습니다. 채우지 않았습니다 — `observed_days()`
  가 그 해를 334일로 세므로 월평균 비교에 지장이 없고, 지어내면 그 달의
  실제 개통·폐쇄를 가리게 됩니다.
- **2004-06** 포털이 6월 요청에 **7월 파일을 줬습니다**(내용이 7월 파일과
  행 단위로 동일). 다시 받아도 같은 것이 올 수 있어 11개월로 둡니다.
  변환기가 이제 파일 이름이 아니라 안의 날짜로 판단하므로, 나중에 제대로
  된 6월을 받으면 그때 붙이면 됩니다.

### 23년 시계열이 스스로를 검증합니다

    2003  145,023,580     —
    2008  166,819,209  +0.0%   ← 금융위기. 23년 중 유일한 정체
    2020  242,796,325  -2.9%   ← 코로나. 23년 중 유일한 감소
    2025  283,002,379  +1.2%

    누적 1.95배 · 연평균 3.1%

두 위기가 정확히 제자리에 있습니다. 이것을 겨냥해 맞춘 것이 아니라,
손상 행을 버리고 승계를 제외하고 관측일수로 나눈 뒤에 남은 모양입니다.

### 왜 2003년까지 받았나

토지·공장 가격은 경제 순환을 탑니다. 몇 해만 보면 그 몇 해가 마침 어느
국면이었느냐에 결과가 좌우됩니다. 순환을 한 바퀴 이상 담으려면
**금융위기(2008) 전후를 포함**해야 합니다.

### 다만 거래는 2006년이 바닥입니다

실거래 신고 의무가 **2006-01** 에 시작됐습니다. 그 이전 거래는 국가가
가지고 있지 않아 어떤 API 로도 받을 수 없습니다.

- 교통량: 2003~2025 (23년) — **완료**
- 거래:   2006~2025 (20년) — 이게 한계입니다
- 짝지어 쓰는 구간: 1년 시차라 **2006년 거래 ↔ 2005년 교통량** 부터

교통량 2003~2005 는 짝이 없지만 장기 추세와 **2·3년 시차 시험**에 씁니다.
2006년 거래에 3년 시차를 걸면 2003년 교통량이 짝이 됩니다.

## 왜 이 문서가 필요한가

확보하신 자료는 **2025년 한 해**뿐입니다. 그러면 이렇게 됩니다.

```
Δln(가격) = β · Δln(교통량, 1년 시차) + ...
                    ↑ 연도가 1개면 Δ 가 존재하지 않음
```

**H2(핵심 가설)를 아예 추정할 수 없습니다.** 최소 3개 연도, 실용적으로는
**8~10년**이 필요합니다.

원인도 짐작됩니다 — 공공데이터포털의
[한국도로공사_**실시간** 영업소별 교통량 (15076872)](https://www.data.go.kr/data/15076872/openapi.do)
은 이름 그대로 **실시간 조회용**이라 과거 시점을 돌려주지 않습니다.
과거 자료는 **파일 데이터**나 **통계연보** 쪽에 있습니다.

### 🥉 3순위 — 실시간 API 를 일별로 백필

> **"실시간 API에 날짜를 하루씩 넣어 365일을 합치면 되지 않나?"**
> — 방향은 맞습니다. 다만 **되는지 여부를 먼저 확인**해야 하고, 되더라도
> 함정이 두 개 있습니다.

#### 확인 1 — 과거 날짜가 실제로 나오는가 (가장 중요)

'실시간' API 는 **보관 기간이 짧은 경우가 많습니다.** 당일 또는 최근 며칠만
주는 API라면 이 방법 자체가 성립하지 않습니다.

```bash
python -m redt.cli probe-history
```

동작하는 엔드포인트·날짜 파라미터를 자동으로 찾은 뒤,
어제 → 1주 → 1개월 → 3개월 → 6개월 → 1년 → 2년 → 5년 → 10년 전 날짜를
차례로 호출해 **어디까지 나오는지** 판정합니다.

| 판정 | 의미 |
|---|---|
| 1년 이상 조회됨 | ✅ 이 방식 유효 — `backfill` 로 진행 |
| 1년 미만 | ⚠️ 연도별 변화(H2)엔 부족 — 파일데이터 병행 |
| 과거 전무 | ❌ 당일만 제공 — 파일데이터 경로로 전환 |

#### 확인 2 — 하이패스 구분 ⚠️ 이걸 놓치면 시계열이 통째로 망가집니다

TCS 자료는 보통 **현금(TCS)과 하이패스가 구분**되어 있습니다.
하이패스 이용률은 지난 10여 년간 계속 상승했습니다.

만약 **현금 통행량만** 뽑아서 연도별로 이으면,
실제 교통량은 늘었는데 데이터상으로는 **급감**하는 것처럼 보입니다.
그 상태로 β를 추정하면 **부호가 뒤집힌 결론**이 나옵니다.

→ 백필 시 하이패스 구분을 그대로 보존(`traffic_daily.hipass`)하고,
   연 집계 때 **합산**합니다. `rollup` 이 구분값 분포를 출력하며,
   값이 하나뿐이면 경고합니다.

#### 확인 3 — 결측일

일별 수집은 API 오류·서버 점검으로 빠지는 날이 생깁니다.
**연 합계를 그대로 쓰면 수집 누락이 '교통량 감소'로 잡힙니다.**

→ 일별 원시 데이터를 `traffic_daily` 에 보존하고, 연 집계 시
   **관측일수로 나눈 `avg_daily`** 를 분석에 사용합니다.
   (검증: `make test` — 관측일수가 절반인 해도 `avg_daily` 가 동일하게 나오는지 확인)

#### 실행

```bash
# 1) 가능 여부 판정
python -m redt.cli probe-history

# 2) 위에서 나온 엔드포인트/파라미터로 백필 (중단해도 이어받음)
python -m redt.cli backfill \
    --endpoint trafficapi/trafficIc --date-param stdDt \
    --start 2015-01-01 --end 2025-12-31

# 3) 일별 → 연 집계
python -m redt.cli rollup

# 4) 확보 현황 판정
python -m redt.cli coverage
```

**예상 규모**: 11년 = 약 4,000일. 하루치가 여러 페이지면 그만큼 곱해집니다.
하루 1초로 잡아도 몇 시간 수준이라 현실적입니다.
`traffic_fetch_log` 에 날짜별로 기록되므로 며칠에 나눠 돌려도 됩니다.

#### 엔드포인트 목록만 보고 싶다면

```bash
python -m redt.cli probe-ex
```

## 받은 파일 적재하기

형식이 제각각(일별/분기별/연별, long/wide, 영업소기준/지점기준)이라
로더가 자동 흡수하도록 만들어뒀습니다.

```bash
# 1) 먼저 컬럼 확인 — wide 형식(연도가 컬럼)이면 자동 감지해서 알려줍니다
python -m redt.cli traffic --path data/raw/tcs_2015_2025.csv --inspect

# 2) TCS 영업소 기준 자료
python -m redt.cli traffic --path data/raw/tcs_2015_2025.csv --source tcs

# 3) AADT 지점 기준 자료 (좌표로 최근접 영업소에 매핑)
python -m redt.cli traffic --path data/raw/aadt.xlsx \
       --source aadt --unit-type point --value daily --max-match-km 5

# 4) 자동 추정이 틀리면 컬럼 직접 지정
python -m redt.cli traffic --path data/raw/x.csv --source tcs \
       --mapping '{"tollgate_id":"영업소코드","volume":"통행량","year":"기준연도"}'

# 5) 확보 현황 및 분석 가능 여부 판정
python -m redt.cli coverage
```

로더가 처리하는 것:
- CSV 인코딩 자동 판별 (utf-8 / cp949 / euc-kr) — 공공기관 파일은 대개 cp949
- **wide 형식**(`2015`, `2016`… 이 컬럼) 자동 감지 → long 변환
- 일별/월별 → 연 집계, **관측일수가 300일 미만이면 경고** (집계 커버리지 변화가
  교통량 변화로 오인되는 것을 막기 위함)
- 일평균(AADT)과 연간누적을 구분해 `avg_daily` / `volume` 양쪽에 저장
- 지점 좌표 → 최근접 영업소 매핑, 여러 지점이 한 영업소에 붙으면 합산

**분석에는 `avg_daily`를 씁니다.** 연 합계는 관측일수가 해마다 다르면
실제 교통량 변화가 아니라 집계 커버리지 변화를 β로 잡아냅니다.

## 만약 과거자료를 끝내 못 구하면

H2는 포기해야 하지만 **프로젝트 전체가 무너지지는 않습니다.**

**H5(지구지정 이벤트 스터디)는 교통량 시계열이 전혀 필요 없습니다.**
실거래가는 2006년부터 공개되어 있어서, 산업단지·택지지구 **지정 고시일**만
모으면 "지정 전후로 땅값이 어떤 궤적을 그렸는가"를 바로 분석할 수 있습니다.

그리고 투자자에게는 이쪽이 더 잘 팔릴 수 있습니다 —
"교통량이 늘면 땅값이 오른다"보다 **"지구지정 후 몇 년째가 매수 적기인가"**
가 훨씬 행동으로 옮기기 쉬운 정보이기 때문입니다.

2025년 교통량 한 해치도 버리지 않습니다.
**현재 수준(level)** 지표로는 유효해서, 스크리닝 화면의
"이 IC는 화물 통행량 전국 상위 몇 %" 같은 표시에 그대로 쓸 수 있습니다.
다만 그건 **상관분석의 근거는 못 되고 참고 지표**라는 선을 지켜야 합니다.
