# 교통량 과거 시계열 확보 경로

## 왜 이 문서가 필요한가

확보하신 자료는 **2025년 한 해**뿐입니다. 그러면 이렇게 됩니다.

```
Δln(가격) = β · Δln(교통량, 1년 시차) + ...
                    ↑ 연도가 1개면 Δ 가 존재하지 않음
```

**H2(핵심 가설)를 아예 추정할 수 없습니다.** 최소 3개 연도, 실용적으로는
**8~10년**이 필요합니다.

원인도 짐작됩니다 — 공공데이터포털의
[한국도로공사_**실시간** 영업소별 교통량 (15076872)](https://www.data.go.kr/data/15076872/openapi.do)
은 이름 그대로 **실시간 조회용**이라 과거 시점을 돌려주지 않습니다.
과거 자료는 **파일 데이터**나 **통계연보** 쪽에 있습니다.

---

## 소스 우선순위

### 🥇 1순위 — TCS 영업소별 교통량 (파일 데이터)

**성격**: 그 IC로 실제 나가고 들어온 통행량. **우리가 원하는 바로 그 지표**입니다.
지역 경제활동을 직접 반영합니다.

| 소스 | 링크 |
|---|---|
| 고속도로 공공데이터포털 파일다운로드 | [data.ex.co.kr → 입출구 교통량(차로별)](https://data.ex.co.kr/portal/fdwn/view?type=TCS&num=65&requestfrom=dataset) |
| 한국도로공사_영업소별 교통량 | [data.go.kr 15043774](https://www.data.go.kr/data/15043774/fileData.do) |
| 한국도로공사_분기별 톨게이트 일교통량 | [data.go.kr 15043784](https://www.data.go.kr/data/15043784/fileData.do) |
| 한국도로공사_구간단면 교통량 TCS 전노선 | [data.go.kr 15043781](https://www.data.go.kr/data/15043781/fileData.do) |
| 한국도로공사_전국 교통량 | [data.go.kr 15062171](https://www.data.go.kr/data/15062171/fileData.do) |

> ⚠️ data.go.kr의 파일데이터는 제목 끝 날짜(`_20200610`)가 **그 시점 스냅샷**이라는
> 뜻인 경우가 많습니다. 파일을 열어 **연도 컬럼이 여러 개인지** 확인하세요.
> 한 해치뿐이면 data.ex.co.kr 파일다운로드 쪽에서 연도별로 받아야 합니다.

### 🥈 2순위 — 도로교통량 통계연보 (지점별 AADT)

**성격**: 본선 조사지점의 **연평균 일교통량**. 차종 구분이 상세하고
**수십 년치 시계열**이 있습니다.

| 소스 | 링크 |
|---|---|
| 교통량정보제공시스템 (한국건설기술연구원) | [road.re.kr](https://www.road.re.kr/) → 통계자료 / 통계연보 |
| 국토교통 통계누리 | [stat.molit.go.kr](https://stat.molit.go.kr/portal/cate/statMetaView.do?hRsId=63) |
| 한국도로공사_연평균일교통량 | [data.go.kr 15062249](https://www.data.go.kr/data/15062249/fileData.do) |

> ⚠️ **본선 지점 교통량은 통과 교통을 포함**합니다. 그 IC를 이용하지 않고
> 지나가기만 하는 차량이 섞여 있어, 지역 수요 지표로서는 TCS보다 약합니다.
> 그래서 `source='aadt'` 로 따로 표시하고, TCS가 있으면 TCS를 우선합니다
> (`settings.yaml` 의 `traffic_source_priority`).
>
> 다만 **장기 시계열이 이쪽에만 있다면 이게 유일한 선택지**입니다.
> 그리고 두 소스가 같은 방향의 β를 주면 그 자체가 강력한 강건성 근거가 됩니다.

### 🥉 3순위 — 도로공사 OpenAPI 탐침

과거 조회가 되는 엔드포인트가 있는지 **직접 시험**해봅니다.
문서가 버전마다 달라 추측보다 확인이 빠릅니다.

```bash
python -m redt.cli probe-ex
```

후보 엔드포인트 × 날짜 파라미터 조합을 모두 시험하고,
**동작하는 것과 그 응답 필드명**을 출력합니다. 결과 알려주시면 수집기를 붙이겠습니다.

## 받은 파일 적재하기

형식이 제각각(일별/분기별/연별, long/wide, 영업소기준/지점기준)이라
로더가 자동 흡수하도록 만들어뒀습니다.

```bash
# 1) 먼저 컬럼 확인 — wide 형식(연도가 컬럼)이면 자동 감지해서 알려줍니다
python -m redt.cli traffic --path data/raw/tcs_2015_2025.csv --inspect

# 2) TCS 영업소 기준 자료
python -m redt.cli traffic --path data/raw/tcs_2015_2025.csv --source tcs

# 3) AADT 지점 기준 자료 (좌표로 최근접 영업소에 매핑)
python -m redt.cli traffic --path data/raw/aadt.xlsx \
       --source aadt --unit-type point --value daily --max-match-km 5

# 4) 자동 추정이 틀리면 컬럼 직접 지정
python -m redt.cli traffic --path data/raw/x.csv --source tcs \
       --mapping '{"tollgate_id":"영업소코드","volume":"통행량","year":"기준연도"}'

# 5) 확보 현황 및 분석 가능 여부 판정
python -m redt.cli coverage
```

로더가 처리하는 것:
- CSV 인코딩 자동 판별 (utf-8 / cp949 / euc-kr) — 공공기관 파일은 대개 cp949
- **wide 형식**(`2015`, `2016`… 이 컬럼) 자동 감지 → long 변환
- 일별/월별 → 연 집계, **관측일수가 300일 미만이면 경고** (집계 커버리지 변화가
  교통량 변화로 오인되는 것을 막기 위함)
- 일평균(AADT)과 연간누적을 구분해 `avg_daily` / `volume` 양쪽에 저장
- 지점 좌표 → 최근접 영업소 매핑, 여러 지점이 한 영업소에 붙으면 합산

**분석에는 `avg_daily`를 씁니다.** 연 합계는 관측일수가 해마다 다르면
실제 교통량 변화가 아니라 집계 커버리지 변화를 β로 잡아냅니다.

## 만약 과거자료를 끝내 못 구하면

H2는 포기해야 하지만 **프로젝트 전체가 무너지지는 않습니다.**

**H5(지구지정 이벤트 스터디)는 교통량 시계열이 전혀 필요 없습니다.**
실거래가는 2006년부터 공개되어 있어서, 산업단지·택지지구 **지정 고시일**만
모으면 "지정 전후로 땅값이 어떤 궤적을 그렸는가"를 바로 분석할 수 있습니다.

그리고 투자자에게는 이쪽이 더 잘 팔릴 수 있습니다 —
"교통량이 늘면 땅값이 오른다"보다 **"지구지정 후 몇 년째가 매수 적기인가"**
가 훨씬 행동으로 옮기기 쉬운 정보이기 때문입니다.

2025년 교통량 한 해치도 버리지 않습니다.
**현재 수준(level)** 지표로는 유효해서, 스크리닝 화면의
"이 IC는 화물 통행량 전국 상위 몇 %" 같은 표시에 그대로 쓸 수 있습니다.
다만 그건 **상관분석의 근거는 못 되고 참고 지표**라는 선을 지켜야 합니다.
