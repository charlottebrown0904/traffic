# 저장소를 Public 으로 전환하기 — 체크리스트

Actions 실행시간(비공개 Free 월 2,000분)을 9월 1~3일 사흘에 다 써서,
개발이 끝날 때까지 public 으로 두기로 했습니다(2026-09-04 결정).
공개 저장소는 Actions 가 무제한입니다.

**개발이 거의 끝나면 다시 private 으로 되돌립니다.** 그때는
`docs/github-private.md` 를 보세요.

---

## 왜 순서가 중요한가

한 번 공개된 커밋은 **되돌릴 수 없습니다.** 남이 복제해 가면 다시
private 으로 바꿔도 그 복제본은 사라지지 않습니다. 그래서 아래는
'하면 좋은 것' 이 아니라 **순서가 있는 절차**입니다.

---

## 1. ⛔ `DATA_GO_KR_KEY` 재발급 — 먼저 해야 합니다

이력에 살아 있는 키가 하나 있습니다.

```
커밋   25292d8  "Update .env.example"   (2026-08-30)
파일   config/.env.example
```

지금 파일에서는 지웠지만 커밋에는 영구히 남습니다. git 이력이 지운
내용까지 보관하는 것이 존재 이유이기 때문입니다.

절차와 새 키를 넣을 곳은 **`docs/api-keys.md` 의 「공개 전환 전에
반드시」 절**에 있습니다. 요약하면:

1. 공공데이터포털에서 디코딩 키 재발급 (옛 키는 그 순간 죽습니다)
2. **Vercel 환경변수**에 새 키를 넣고 재배포합니다 (GitHub Secrets 는 필요 없습니다 — 키를 끼워 넣는 것은 중계기입니다)
3. 동작을 확인합니다
4. **그 다음에** public 으로 바꿉니다

**fork 는 지울 수 없습니다.** 공개 기간에 누가 fork 하면 나중에 private
으로 되돌려도 그 fork 는 남습니다.

## 6. 가입은 admin 수락형입니다 (2026-09-04)

저장소가 공개돼도 **서비스는 아무나 못 씁니다.** 가입하면 승인 대기
상태가 되고, 관리자가 승인해야 지도와 게시판이 열립니다.

- 승인 화면: `/account` 에 관리자로 로그인하면 대기자 목록이 나옵니다
- 실제 자물쇠는 데이터베이스의 RLS 입니다 — 화면을 우회해도 승인 안 된
  계정은 글도 댓글도 못 읽습니다

같이 막은 것: `profile.role` 을 **자기가 바꿀 수 있었습니다.** 로그인한
사람이 스스로 관리자가 될 수 있는 상태였고(2026-09-04 감사에서 확인),
트리거로 막았습니다.
