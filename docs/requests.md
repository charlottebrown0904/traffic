# 지시를 주고받는 방법 (2026-09-13 합의)

슬라이드로 받은 첫 지시(「토지 고고 수정」 4쪽)가 채팅보다 약 50배 비쌌습니다 —
PDF·PPTX 로 내보내 그림을 따로 읽어야 했고, 슬라이드 안에 이력을 쓸 수도
없었습니다. 그래서 이렇게 정했습니다.

## 지시는 채팅에

- 번호 목록 한 메시지. 한 항목에 「어디 · 무엇을 · 어떻게」 한 줄.
- 캡처는 채팅에 바로 붙인다(빨간 표시 그대로). 폭 1,000px 안팎, 바뀔 부분만.
- 「결정 필요」는 그렇게 적는다 — 선택지를 만들어 먼저 묻는다.
  「더 묻지 말 것」도 미리 적으면 왕복이 준다.
- 서너 건을 한 번에 묶는다. 코드를 한 번 읽고 한 커밋으로 처리한다.
- 긴 자료(비준표·평가서)는 파일이나 드라이브로 — 이것은 직접 읽는다.
- 슬라이드는 새 화면의 배치를 그릴 때만. 그때도 장마다 PNG 로 채팅에.

## 이력은 GitHub Issue 에

- 지시 하나에 이슈 하나. 반영하면 결과를 적고 닫는다.
- 라벨 세 가지 — 슬라이드 1쪽의 범례를 그대로 옮긴 것이다.
  - `반영 완료` — 다시 확인하지 않는다.
  - `불가` — 이유 한 줄. 다시 확인하지 않는다.
  - `추후 확인` — 사용자가 할 일이나 제안. 다시 본다.
- **회원 이메일·이름이 보이는 캡처는 이슈에 올리지 않는다.** 저장소가
  공개다. 그런 캡처는 채팅에만 붙인다.
- 이전 것은 「이슈 12번」처럼 번호로 가리킨다. 문서를 다시 붙이지 않는다.

이 대화가 압축돼도 이슈와 커밋은 남는다 — 이력은 여기가 원본이다.
